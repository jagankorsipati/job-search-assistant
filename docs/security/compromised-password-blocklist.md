The input contains exactly 10,000 entries and produces exactly 10,000 digests. The tracked resource contains no plaintext passwords. Its v2026.1 format is provenance comments followed by one lowercase hexadecimal SHA-256 digest per UTF-8 source line, sorted and unique. Startup validates the version header, line format, ordering, uniqueness, and minimum coverage; invitation acceptance fails closed if validation fails.

Deterministic regeneration from the repository root is `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\generate-compromised-password-blocklist.ps1`. The generator downloads only the exact commit URL and fails on checksum, input shape/count, output count, duplicate, ordering, or metadata mismatch. To review an update, change the commit, human-reference release, version, expected counts, and checksum together; verify the upstream license and source; regenerate; inspect the provenance header and diff; then run the complete backend verification. Updating the list is a reviewed security change, not an automatic network operation at application runtime.
