# Phase 5 Verification Matrix

Phase 5 covers manual job-requirement review, owner-selected candidate-evidence links, deterministic `DETERMINISTIC_FIT_V1` analysis, explainable fit-review UI, optimistic locking, and privacy-preserving browser verification.

| Area                                   | Evidence                                                                                                                                                                                                                                                                                                                                                                                                                 |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Requirement and snapshot ownership     | Flyway V10 creates owner-scoped requirement and evidence-link tables tied to captured jobs and immutable job-description snapshots. Backend API tests prove owned snapshot access, safe 404 behavior for foreign job/snapshot combinations, and no ADMIN bypass.                                                                                                                                                         |
| Evidence-reference ownership           | Backend tests cover confirmed career facts, supported profile fields, base resume version metadata, rejection of draft/foreign evidence, duplicate-link conflicts, and deletion blocking while links exist. Browser tests verify only eligible owner evidence is offered.                                                                                                                                                |
| Manual review controls                 | Frontend component tests and `frontend/e2e/fit-analysis-security.spec.ts` verify requirements are created manually, default to draft, require deliberate confirmation before scoring, can be rejected or returned to draft, and are not extracted automatically.                                                                                                                                                         |
| Explicit evidence relationships        | Domain/API/component/browser coverage proves evidence links are user-selected, have no preselected relationship, support `SUPPORTS`, `PARTIALLY_SUPPORTS`, `NOT_DEMONSTRATED`, and `CONTRADICTS`, use optimistic versions, and are never created automatically.                                                                                                                                                          |
| Deterministic scoring policy           | `FitScoringPolicyTests`, `FitAnalysisServiceIT`, `FitAnalysisApiIT`, and browser assertions cover non-scorable results, exact support/coverage examples, half-up rounding, draft/rejected exclusion, contradiction/conflict zero contribution, and no score inflation from multiple links.                                                                                                                               |
| Explainability and truthfulness        | The fit workspace states that analysis uses only confirmed requirements and user-selected evidence relationships, does not predict hiring decisions, and does not independently verify qualifications. Browser assertions reject misleading hiring-probability, qualified/unqualified, recruiter-score, guaranteed-match, and "you lack this skill" claims in the fit workspace.                                         |
| Fresh, non-persisted analysis          | Fit-analysis API responses use `Cache-Control: no-store`; integration tests prove analysis is recomputed without writing score/history rows. Packaging inspection confirms no extra migration beyond V10 and no frontend/test artifacts in the production JAR.                                                                                                                                                           |
| Optimistic locking                     | Backend API tests and browser E2E cover stale requirement and evidence-link writes returning safe 409 behavior, preserving unsaved browser input, requiring explicit reload, and preventing overwrites.                                                                                                                                                                                                                  |
| CSRF and sessions                      | Backend tests and browser E2E verify unsafe requirement/evidence mutations require CSRF, fit-analysis GET requires authentication but not CSRF, anonymous fit routes return to login, session cookies remain HTTP-only/SameSite, and production rate-limit defaults remain unchanged.                                                                                                                                    |
| Bounded analysis                       | `FitAnalysisApiIT` verifies `analysis_too_large` returns 409 without a partial score or private data, using bounded synthetic setup and the production limit. Frontend component tests verify the safe explanation while preserving the last confirmed analysis.                                                                                                                                                         |
| Browser privacy and network boundaries | Browser E2E verifies fit data is absent from localStorage, sessionStorage, IndexedDB names, URLs, and cookies; posting URL hosts, AI providers, job boards, analytics providers, and unknown external hosts are not contacted.                                                                                                                                                                                           |
| Diagnostics and cleanup                | Playwright screenshots, videos, traces, HTML reports, blob reports, raw error contexts, persistent browser profiles, downloads, and synthetic uploads remain disabled or discarded. `scripts/run-browser-e2e.ps1` emits only sanitized text diagnostics and removes disposable containers, volumes, temporary logs, and browser artifacts.                                                                               |
| CI coverage                            | The existing browser CI job discovers all Playwright specs through `scripts/run-browser-e2e.ps1` in one disposable PostgreSQL/backend/frontend environment with one worker and process-scoped E2E rate-limit overrides only.                                                                                                                                                                                             |
| Residual limitations                   | Phase 5 intentionally keeps requirement extraction manual, evidence selection manual, no semantic matching, no resume tailoring, no generated recommendations, no job ranking, no persisted score or history, no cross-snapshot comparison, no reminders, no notifications, no automated application submission, and no external integrations. Fit results depend on completeness and accuracy of user-confirmed inputs. |
